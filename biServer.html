BI Server — Architecture & Setup Guide

How the Salesforce AI Chatbot accesses real-time LexisNexis Redshift data

Python FastAPI AWS Redshift Salesforce Apex MCP Server

Overview

The Salesforce AI Chatbot needed access to real BI metrics from LexisNexis's internal Redshift data warehouse (gdw database on prod-gdw-database.business.aws.lexisnexis.com). The warehouse contains Salesforce-mirrored tables (opportunities, cases, activities) alongside billing and revenue data going back to 2015.

A Python server acts as a bridge: Salesforce calls it over HTTP, it queries Redshift, and returns structured JSON that the chatbot's LLM uses as context. The same server is registered as an MCP server with Claude Code, so the AI can query the database directly during development.

Data Flow — Step by Step

1
User sends a message in the chatbot chatbotShell LWC fires sendMessage(recordId, objectApiName, message) to Apex.
2
ContextBuilderService builds the context Queries the current Salesforce record + related objects. Extracts the entityId — first tries SourceSystemIdentifier__c / External_Id__c, falls back to the Salesforce record ID (18-char).
3
ExternalBIService makes an HTTP callout Calls GET callout:External_BI/metrics?entityId={sfRecordId} via Named Credential. The server runs on port 8000 (local/ngrok) or API Gateway (prod).
4
api_server.py resolves the join key Queries ei.sf_opty_curr WHERE sf_intgrt_acct_id = entityId to get the Redshift internal acct_id. This is the bridge between the Salesforce ID namespace and Redshift's internal IDs.
5
Parallel Redshift queries Fetches open opportunities (ei.sf_opty_curr), cases (ei.sf_case), monthly revenue (ei.earned_rev_mthly_sum), and activities (ei.sf_activity).
6
JSON returned to Salesforce The response is stored in the context map as biData and injected into the LLM system prompt alongside the Salesforce record data. GPT-5.5 then uses both sources to answer the user's question.

Key Database Join — Salesforce ID → Redshift Revenue

The central discovery: ei.sf_opty_curr.sf_intgrt_acct_id stores the Salesforce Account ID, linking CRM data to all billing and revenue tables.

-- Step 1: resolve SF Account ID → Redshift internal acct_id
SELECT acct_id
FROM   ei.sf_opty_curr
WHERE  sf_intgrt_acct_id = '001f400000wwOihAAE'   -- Salesforce 18-char ID
  AND  acct_id <> 'NA'
LIMIT  1;
-- → acct_id = '42532G3MB'

-- Step 2: pull monthly revenue using acct_id
SELECT clndr_yr, clndr_month,
       SUM(usd_net_earned_rev_amt) AS net_rev_usd
FROM   ei.earned_rev_mthly_sum
WHERE  acct_id = '42532G3MB'
GROUP BY clndr_yr, clndr_month
ORDER BY clndr_yr DESC, clndr_month DESC
LIMIT  12;

Running the Server

Local Development

# From the bi-server/ directory
cd bi-server
source venv/bin/activate

export REDSHIFT_HOST=prod-gdw-database.business.aws.lexisnexis.com
export REDSHIFT_DATABASE=gdw
export REDSHIFT_PORT=5439
export REDSHIFT_USER=patelgv
export REDSHIFT_PASSWORD='your-password'

uvicorn api_server:app --host 0.0.0.0 --port 8000

Expose to Salesforce via ngrok (development)

ngrok http 8000
# Copy the https://xxxx.ngrok.io URL

Production Deployment (AWS Lambda)

For Salesforce to call Redshift from the cloud, deploy lambda_handler.py as a Lambda function inside the same VPC as the Redshift cluster.

# 1. Package the function
pip install -r requirements.txt -t ./package
cp *.py ./package/
cd package && zip -r ../bi_lambda.zip . && cd ..

# 2. Deploy via AWS CLI
aws lambda create-function \
  --function-name bi-server \
  --runtime python3.12 \
  --handler lambda_handler.handler \
  --zip-file fileb://bi_lambda.zip \
  --role arn:aws:iam::ACCOUNT:role/lambda-redshift-role \
  --vpc-config SubnetIds=subnet-xxx,SecurityGroupIds=sg-xxx \
  --environment Variables="{REDSHIFT_HOST=...,REDSHIFT_USER=...,REDSHIFT_PASSWORD=...}"

# 3. Add API Gateway trigger → copy the HTTPS URL → update Named Credential
