What is Intent Recognition?

Key insight: In this chatbot, GPT-4o acts as both the intent classifier and the response generator in a single API call. There is no separate NLP pipeline — the LLM reads the user's message alongside strict schema rules and returns a typed JSON object where responseType is the intent.

Traditional Approach

Two separate steps — classify first, then generate.

1
NLP ClassifierRegex / ML model identifies intent ("summarize", "create", "chart"…)
2
Response GeneratorSeparate LLM call generates the actual response content
3
RendererUI picks a component based on the classified intent

This Chatbot's Approach

One call — classify and generate together.

1
Single GPT-4o CallSystem prompt enforces response_format: json_object with 9 typed schemas
2
JSON ResponseLLM returns responseType (the intent) + all data in one structured object
3
RendererLWC routes to the correct visual component by responseType

End-to-End Flow

The 9 Intent Types

GPT-4o selects one of these schemas based on the user's message. Each maps directly to a dedicated LWC visual component.

record_summary

Record Summary

Rich overview of the current record — header, KPI bar, and related-record sections with clickable links.

"Summarize this account" "Give me an overview" "Review this record"
record_action

Record Action

Creates or updates a Salesforce record. Renders a confirmation card with field table before executing DML.

"Create a follow-up task" "Update the phone number" "Add a new contact"
kpi_cards

KPI Cards

Metric tiles with trend indicators, icons, and directional arrows. Used for counts, amounts, and performance numbers.

"Show me the metrics" "How many open opps?" "What's the pipeline value?"
chart

Chart

Bar, line, or donut chart rendered with Chart.js. Used for trends over time and distributions.

"Show revenue trend" "Chart monthly activity" "Opportunity stage breakdown"
alert

Alert

Severity-based banner (critical / warning / info / success). Used for risks, anomalies, and action feedback.

"What are the risks?" "Any issues I should know?" "Is anything overdue?"
timeline

Timeline

Chronological event list with status badges and type icons. Used for activity history and project phases.

"Show activity history" "What happened recently?" "Key milestones"
comparison

Comparison Table

Side-by-side table of Salesforce values vs external system (ERP/BI). Highlights discrepancies.

"Compare SF vs ERP data" "What's different in BI?" "Data discrepancies"
table

Table

Sortable multi-column data table. Used for pricing, SKU lists, schedules, and any structured tabular data.

"Show pricing table" "List all line items" "Product catalog"
summary

Summary

Narrative answer with headed sections and color-coded badges. The fallback intent for open-ended questions.

"Tell me about this account" "Explain the situation" "What do you know about…"

How GPT-4o Decides the Intent

1 — Strict Schema Enforcement

The API call includes response_format: json_object, forcing GPT-4o to return only valid JSON.

// LNChatLLMService.cls
Map<String, Object> requestBody =
  new Map<String, Object>{
    'model'    => modelName,
    'messages' => messages,
    'response_format' =>
      new Map<String, String>{
        'type' => 'json_object'
      }
  };

2 — Schema Selection Rules in System Prompt

Key rules that drive intent selection:

R8
record_action is mandatory for create/updateNever tell the user to do it manually.
R13
record_summary is mandatory for "summarize"Always use Schema 7 for overview requests.
R1
Never default to summaryWhen numbers, trends, or timelines are present, pick the richer type.
