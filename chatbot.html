End-to-End Architecture

Overview

The chatbot is embedded as a Utility Bar component (or placed on any record page via chatbotDrawer). When a user opens any record page (Account, Contact, Opportunity, Case, Lead), the chatbot auto-detects the page context and provides AI-powered answers and actions for that specific record.

Every message goes through a callout pipeline: Salesforce context is built (SOQL), external data is fetched (ERP + BI), then the LLM is called (OpenAI GPT-4o) — up to 4 HTTP callouts total, since Account summary turns add one more OpenAI web-search callout that fetches recent company news (rendered as "Results from the Web"). All HTTP callouts happen before any DML to comply with Salesforce's callout-before-DML governor restriction. Users can optionally attach image, PDF, or text files for analysis in the same turn.

The LLM responds with one of 10 structured JSON response types — rendered by dedicated LWC child components for rich visual output: KPI cards, charts, comparison tables, timelines, alerts, record summaries, record lists, and record action confirmation cards. A scheduled Apex batch also delivers a weekly email digest per rep with AI-generated account health insights.

chatbotShell owns all state. responseRenderer routes to the correct visual component by responseType. chatbotDrawer provides a floating FAB for non-utility-bar pages. activityTimeline renders a horizontal Tasks+Events timeline.

Architecture Diagram

Read Flow — Answering a Question

1
User types a message in chatbotInput (optionally attaches a file) The textarea fires a messagesend custom event with { message, attachment }. Attachment is a JSON object produced by the browser FileReader API. Suggestion chips fire the same event with pre-defined prompts: Summarize this record, Meeting prep, Log a call (prefills template), Draft follow-up email (prefills template), What are the next steps?, Open Opportunities, What are the risks?
2
chatbotShell calls ChatbotController.sendMessage() Passes userMessage, recordId, objectApiName, serialized conversationHistoryJson (last 10 turns), and attachmentJson (null if no file). On API failure the user message is popped from conversationHistory so retries don't inflate context.
3
ContextBuilderService.buildContext() — SOQL phase Dynamic SOQL queries all fields on the current record. Queries related objects per page type: Contacts (10), Opportunities (10), Cases (10), Tasks (10), Orders (5), Contracts (5), Quotes (5) — each individually try-caught so missing/disabled objects silently skip.
4
ExternalERPService.getRecordData() — HTTP callout 1 POST to callout:External_ERP. Returns order history, billing, inventory data. Returns available: false on failure — never blocks the main flow.
5
ExternalBIService.getMetrics() — HTTP callout 2 GET to callout:External_BI/metrics?entityId={sfId}. Python FastAPI resolves the Salesforce ID to a Redshift acct_id and returns revenue, open opportunities, cases, and monthly trends.
6
LLMService.chat() — final HTTP callout POST to callout:OpenAI_GPT/v1/chat/completions. Builds a multimodal messages array: system prompt (10 response schemas + 19 rules), context JSON (incl. webData when present), conversation history, user text message, and optional image/PDF/text attachment block. Model: GPT-4o. max_completion_tokens from AI_Config__mdt (must be ≥ 4096). 429 rate limit triggers one retry. Note: on Account summary-intent turns, WebService.getCompanyOverview() first makes a separate web-search callout (gpt-4o-search-preview) to fetch recent company news — grounded results land in data.overview (Rule 19) and render as "Results from the Web".
7
enrichSummaryRecordIds() — post-processing For record_summary responses: builds a name→Id map from context and injects missing Salesforce record IDs into section items so they render as clickable links.
8
DML — session + message persistence All callouts complete — DML is now allowed. getOrCreateSession() upserts a ChatSession__c. saveChatMessage() inserts user and assistant ChatMessage__c records (content truncated at 131,072 chars). Attachment data is not persisted — it is one-shot context for the current turn.
9
responseRenderer routes to the correct display component Reads responseType and renders: kpiCardGrid, chartWidget, comparisonTable, timelineView, alertBanner, recordActionCard, recordSummary, or inline summary sections.
⚡ Callout Order
① ERP callout → ② BI callout → ③ Web search (Account summary only) → ④ OpenAI callout → ⑤ getOrCreateSession() DML → ⑥ saveChatMessage() DML

Write Flow — Creating or Updating a Record

1
LLM returns responseType "record_action" When the user asks to create or update a record. The LLM automatically applies parent associations (AccountId, WhatId, WhoId) based on the current page object and applies required field defaults (CloseDate, StageName, Status, etc.).
2
recordActionCard renders a confirmation card Shows operation (Create/Update), object type, and a field table. User clicks Confirm or Cancel. Confirmation fires a recordactionconfirm event that bubbles up to chatbotShell.
3
ChatbotController.executeRecordAction() Calls RecordActionService.executeAction() with objectApiName, operation (create/update), recordId (for updates), fields map, currentPageRecordId, and bypassDuplicate flag.
4
Ambiguity check (UPDATE only — skipped for current page record) Searches for other records with the same name/identity fields. If multiple matches found → blocked. Returns a response listing all candidates with their Record IDs so the user can specify which one to update.
5
Duplicate value check (CREATE + UPDATE) Checks whether the new field values collide with existing records. Contact: Email → FirstName+LastName. Account: Name. Opportunity: Name+AccountId. Case: Subject+AccountId. If duplicate found and bypassDuplicate=false → blocked with "Proceed Anyway" option.
6
DML — insert or update SObject Performs the actual insert or update. Returns the new/updated record ID. chatbotShell renders a success alert; the user can click the Record ID to navigate directly to the new record.

File Attachment Flow

Users can attach a file using the + button in chatbotInput. The file is read entirely client-side using the browser's FileReader API and serialized as JSON. This JSON is passed through the messagesend event → chatbotShell → ChatbotController.sendMessage(attachmentJson) → LLMService.chat(attachmentJson), where it is included in the multimodal OpenAI message for the current turn only.

Attachments are not persisted to ChatMessage__c — only the text content of each turn is stored. The attachment pill shown in chatbotHistory is a UI-only affordance derived from the filename passed to addMessage().

The 3 MB limit for images/PDFs stays within Salesforce's @AuraEnabled request-body practical limit (~4 MB after base64 encoding overhead). Text files are capped at 500 KB. LLMService messages list uses List<Map<String, Object>> (not String) to support both plain text and multimodal content arrays as values.

Key Constraints & Design Decisions

Salesforce Governor Limits

🔢
Up to 4 HTTP callouts per transaction ERP (1) + BI (2) + OpenAI (3), plus an optional Web-search callout (4) on Account summary-intent turns. Still well under the 100-callout limit; all precede DML.
⚡
Callouts must precede all DML All 3 callouts complete in ContextBuilderService + LLMService before getOrCreateSession() DML runs.
📊
SOQL query limit (100 per transaction) Related queries per object capped + individually try-caught.
💾
LongText field limit Content truncated at 131,072 chars before insert.

LWC Constraints

🚫
@api data is a reserved LWC prop name All data props named cardData, tableData, chartSeries, etc. instead.
📈
Chart.js LWC proxy mutation error Chart.js adds a _chartjs property to data arrays; LWC proxies are read-only. Fix: always clone with Array.from() before passing.
🔧
Utility bar FlexiPage cannot be deployed via CLI Both AI_Assistant_UtilityBar.flexipage-meta.xml and AI_Assistant.app-meta.xml are in .forceignore. Configure via Setup → App Manager UI.
🔑
webservice is a reserved Apex keyword Apex identifiers are case-insensitive, so a local variable named webService fails to compile ("Unexpected token"). Use webSvc.
🌐
Org-safe source detection TimelineService builds its SOQL field list dynamically via Schema describe, referencing Gong__*/SalesLoft1__* fields only when present — deploys everywhere; lights up real sources only where those packages exist.
📁
File attachment limits Images/PDFs: ≤ 3 MB (pre-encoding). Text files: ≤ 500 KB. Stays within @AuraEnabled request-body limits (~4 MB after base64 overhead).

Security

🔒
Record-level security All Apex classes use with sharing — users only see records they have access to.
🔑
API key never in source Stored in protected AI_Config__mdt. Source file in .forceignore so CLI deploy never overwrites the live key.
🛡️
LLM output rendered as structured data Never as raw HTML — eliminates XSS risk from AI-generated content.

Token Limit

⚠️
MaxTokens must be ≥ 4096 Values ≤ 2000 cause OpenAI to return finish_reason: "length" with an empty content field for large record contexts (full system prompt + Salesforce data). LLMService raises a descriptive error on detection.
🔄
Conversation history pop-on-error chatbotShell pops the user message from conversationHistory in the catch block so failed attempts don't accumulate and inflate context on retry.
📝
Attachments are one-shot context only File data is not persisted to ChatMessage__c. Each attachment is included in the LLM call for that turn only. Conversation history stores text only.
